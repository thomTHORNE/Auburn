# Tests

A deliberate, measured set: the hard measure of strength that graded training does not give. Chosen by the user, never rolled.

## Settled

- **Graded training and tests have different jobs.** Grading reads a set by feel; a test measures it. Tests accumulate into a provable measure of strength over time.
- **A test is the user's choice.** Auburn never rolls or schedules one.

## Open questions

- **What a test records.** Load, reps and grade, and whether reps are required, which Foundation's "Auburn never requires a rep count to log a set" would have to allow.
- **What it marks.** A set, a commit, or a workout.
- **How tests show.** A line of their own in Progress, or the reps line.
- **Goals.** Whether a reps or load target is proven only by tests.
- **Programming.** Whether a programming entry can call for a test, such as every four weeks.
- **The roll.** Removed when tests land, and with it the modality. What becomes of slow and controlled.
- **Foundation.** How "Variety on purpose" and the rep-count refusal change.

## Findings

- **The roll began as a way to get a hard measure.** Its counted modality was meant as a test: a rep count alongside the grade, accumulating over time.
- **Under the roll, a test cannot be planned.** A counted set comes about one commit in three, never chosen.
- **A rolled modality collides with programming.** A goal's method names exercises and sets; the roll changes how those commits are done, at random.
- **Reps mean something only beside a grade.** Seven reps graded Ideal is the max that held; eight reps alone says nothing.

## Dependencies

- **Requires:** none.
- **Required by:** Programming, if an entry can call for a test.
